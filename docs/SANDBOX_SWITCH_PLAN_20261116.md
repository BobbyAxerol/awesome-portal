### 3.3 `pin_m0_scopes` (`target_catalogue_scopes.rs:63-95`): needed?
It is a separate, optional second stage that pins the TS-reviewed S1 scope declarations (account_balances parent join with predicate `mode = paper`, portfolios as shared reference) into both hashed surfaces. It hard-codes `database trading_system`, `profile_mode paper`, the two Paper profile ids, the descriptor `environment paper` and the predicate value `"paper"` (line 45), and checks the S1 contract/statement hashes (Paper literals). The Paper sets that run today (T2, T1) were NOT passed through it (status `PARTIAL_CANDIDATE_NOT_INSTALLED`), so the Sandbox sets do not need it for parity. Extending it would take: accept `(sandbox, trading_system_sandbox, SANDBOX_BINANCE_USDM/BINANCE)` in the guard, derive the predicate value from the profile mode instead of the literal, accept environment/profile_mode `sandbox` in the descriptor check, confirm the S1 source contract/statements pins are database-independent, plus a mirror of the existing Paper tests: about 10-15 lines and tests. Recommendation: not part of this switch.
