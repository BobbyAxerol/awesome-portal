## 2. Constraints from tests (rule + where + how to satisfy)

1. No raw colour outside tokens - `src/styles/tokens.test.ts` first test; `COLOR_PATTERN` also bans `rgba(`, `hsl(`, `oklch(`, `color-mix(`, named colours after `:`; scans EVERY `.ts/.tsx/.css` in `src` except `tokens.css/tokens.ts/tokens.test.ts`. -> all hex/rgba live in tokens.css; v2 css and tsx use `var(--x)`. (Also applies to hand-written test fixtures in `v2/*.test.ts`: no `#fff` strings.)
2. Text pairs in execution.css only - `tokens.test.ts` "contrast of pairs the stylesheet itself declares": `declaredPairs()` reads ONLY `execution/execution.css`; any block with `color: var(--a)` and `background: var(--b);` needs both declared as `#hex;` in the carbon block and >= 4.5:1. The kit's `--c/--bg` indirection (`color:var(--c);background:var(--bg)`) would FAIL if put in execution.css ("does not declare --c"). -> write `.exec-flag[data-k="ok"]{color:var(--f-ok);background:var(--f-ok-bg);border-color:var(--f-ok)}` per kind (no indirection). Because v2 css is not read by this test, U7 adds the same scan for `v2/css/*.css` (see s5).
3. Token parsing - `themeTokens()` ends the block at the first `"\n}"` and keeps only `--x: #hex;` lines; a non-hex value (the hatch rgba) is simply ignored. Keep every new token one-per-line `--name: #rrggbb;` so the pair gates can see it. Do not add a nested rule or a `}` at column 0 inside the block.
4. Canvas mirror - `tokens.ts` `CANVAS_TOKENS` mirrors ONLY `research` and `operations` themes (tokens.test "mirrors tokens.css values"); carbon is not mirrored. -> no `tokens.ts` change in S0. If S0 charts need literal colours for canvas, add a separate carbon map later with its own parity test; do not touch the two existing maps.
