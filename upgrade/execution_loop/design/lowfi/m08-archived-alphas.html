Annotations
  1. Lifecycle, not a stage. “Archived” is a decision label. Previous stage stays Paper / Sandbox / Canary / Live and is shown as a pill; there is no fifth stage and these alphas are not in Fleet's stage tabs by default. An archived alpha that still holds capital or obligations stays inside fund NAV and score denominators (guide §13).
  2. No 7D / 30D picker here. Evidence runs from the day the monitor actually started, so a window picker would mislabel it. Monitor figures are always tagged “Paper · simulated”.
  3. Summary = counts only. No money on this strip. Monitor groups add up to the total (9 + 3 + 5 = 17). Researchers do not see this strip, since fund-level counts would reveal peers.
  4. Lifecycle tabs follow the archive command: requested → pending drain → archived. A row becomes “Archived” only on an authority receipt for the right scope, never from our own click.
  5. Obligations column. What is still open, as counts. Archive does not cancel, flatten or return capital by itself. “None” appears only when known; otherwise “Not available”. An unknown outcome is shown as unknown, not as open or closed.
  6. Monitor column is independent of the original alpha: running / paused / stale / failed / quota-limited / not provisioned. A running monitor does not prove the original is flat.
  7. Evidence cell. Net return and drawdown since the monitor started, labelled simulated, with gaps called out. QBTS reads “Policy pending”; regime support reads “Insufficient data”. Wording is descriptive only: no “likely”, no “recommended”.
  8. Peek drawer keeps the list context. Two timelines are drawn separately on purpose: prior real-funded history and the forward paper monitor are never one continuous line, and the monitor is never backfilled.
  9. Reactivation is a review. Opens a form (below the table), default target Paper, bound to a version. It cannot go live or lift the archive, and a high score does not change that. Researchers see it disabled with a plain reason.
  10. Empty states are first-class. Three different screens: Source not ready (backend has no archive read yet, request FE-016 — so this is the real first state), Zero archived (a true empty result, toggle in the bar) and Loading. Unavailable never shows 0.
  11. Alternative considered: a kanban with lifecycle columns (Requested → Pending drain → Archived → Monitoring → In review). Rejected: obligations, monitor and review are independent facts, so one column position would hide the others and imply a single path.
