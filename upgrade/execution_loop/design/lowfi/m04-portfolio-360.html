Annotations
  1. Tabs live in the URL (/portfolios/pf_0001/risk?env=live&window=30D). Back/forward and deep links keep tab, window and environment. Six tabs; the researcher only sees Overview and Alphas.
  2. Return label. Modified-Dietz, shown under the number; never called TWR. Environment and partition chips stay in the header so every number has a stated basis.
  3. Capital statement. One partition and currency. Initial funds, Added funds and Returned capital are a cash-flow list that adds to net external flows, then profit, then current capital. They are not two track records. The Initial|Added split lives under a disclosure and reads Not available until per-source attribution exists. Budget sits in its own block because budget is not cash and not capital.
  4. Scores. Pending today, with no number, band or colour. The dashed "FUTURE" box shows the intended layout only once the policy qualifies (value, band word, Provisional badge, version, window) and is labelled so it cannot be mistaken for real data.
  5. Attention. Only consequential items with target, time, and where to go.
  6. Allocation hierarchy. Three column groups, never summed together: Budget (allocation), Exposure (position notional) and Native margin (venue-reported). Margin is shown per account only, since venue profiles differ. Pending recall and Locked sit on the row they affect.
  7. Shared account marker on the deployment row, linking to the Accounts tab warning.
  8. Alphas. The Fleet scoped to this portfolio, same columns and server-side sort. Share of PnL is computed on this row set only; offsetting rows can be negative. The link keeps the Portfolio filter.
  9. Shared-account warning. Says that other sleeves exist without counting or naming them, so a manager cannot infer hidden data. Venue balance is labelled as the venue total.
  10. Risk & Health. Missing items (exposure cap, correlation) read "Not available" with a reason, never 0 and never "diversified".
  11. People. Current grants vs attribution-only are separate columns of meaning; history does not give access.
  12. Activity. Authoritative command state and projection state are separate chips (guide section 14). "Outcome unknown" is a state of its own with a status lookup, not a failure and not a retry button.
  13. Action menu. Every action shows its capability state and, when off, a short reason from a shared copy dictionary (FE-015) that never names hidden alphas, owners or amounts. Lock/unlock reads "not offered in the portal yet" because that control is not mounted. There is no "Move money" button: grant, recall and return are separate commands with separate consequences.
  14. Confirmation preview. Target IDs, amount and unit, expected version, authority reason and open obligations, plus a stamp that nothing is applied. Cancel and close never submit. A receipt only appears after submit and starts as accepted, not applied.
  15. Researcher. Own-slice banner, Overview and Alphas only, own allocation and PnL, no totals, no share-of-portfolio, no peer list, no actions.
  16. Alternative considered: master-detail split (portfolio list on the left, 360 on the right). Rejected: it halves the width the three-basis allocation table needs, duplicates M02, and puts a peer list next to a researcher's slice.
