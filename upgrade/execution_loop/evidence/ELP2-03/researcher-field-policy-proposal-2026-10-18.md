# FE-026 — finite own-researcher field-policy proposal

PROPOSED_FOR_BOBBY_REVIEW / NOT_INSTALLED. This is not a grant, approved policy
revision, working own-slice endpoint, native acceptance, or consumer ACK.
The existing reviewed policy and current-source authorization continue to win.

## Boundary

Research ownership does not imply deployment ownership, Portfolio membership,
economic ownership, account access, approval authority, or deployer identity.
An association must bind the immutable Alpha version and exact authorized
Execution resource/environment/workspace; an Alpha name alone is insufficient.
Both Core app policy and genuine current TS/source acceptance remain required.
Protected owner administration is unchanged; it does not confer TS authority.

Proposed own-slice presentation uses a separately reviewed finite field purpose.
It must not return a masked existing Manager row with invented IDs/amounts to
satisfy that row's required schema. Until approved and implemented, consumer
keeps this variant hidden/typed Not published; no policy is promoted by this
document and no additional identity or source lookup is authorized here.

## Proposed field matrix

| Field or group | Own researcher proposal | Required authority / reason |
|---|---|---|
| Own Alpha ID, immutable Alpha-version ID, approved display name | Visible for own bound slice | Research read plus exact version association and Execution field-purpose acceptance; no name-based join. |
| Own researcher identifier | Self identifier only | Existing authenticated self identity; no user directory/email/team enumeration. |
| Research run ID/display label, research evidence reference | Visible only if that Research workspace/run is independently readable | Execution association is not a Research read grant; evidence reference is not the evidence bytes. |
| Own version's recorded stage/gate facts, recorded decision/receipt references | Visible for the own bound slice when actually published | Exact reviewed lifecycle purpose; recorded state is not effective TS deployment state. Missing stage times remain typed absence. |
| Own-slice performance/Score/regime values | Visible only for an accepted own-slice source/basis/purpose | Exact quality, window, methodology, source policy and calibration apply. Do not show Portfolio total as researcher performance. |
| Own deployment observation times/quality/blockers | Visible when separately authorized for that own deployment | Exact deployment-purpose/current source; no claim that a notification is a business event. |
| Portfolio display name | Hidden by default; show public copy 'Your research slice' | A linked Alpha does not grant Portfolio discovery/name access. Existing separate Portfolio read can authorize its own non-researcher view. |
| Portfolio/account/deployment source IDs outside the approved association footprint | Hidden | Avoid a related-resource directory or cross-owner graph. A new association payload needs explicit reviewed ID fields. |
| Portfolio NAV/economic capital/allocation, target budget, backing/exposure limits, fees/funding/currency ledger | Hidden in researcher variant | Requires independent economic/account/Portfolio purpose; research ownership is not capital authority. |
| Custody balance, account labels/credentials, broker/venue private references | Hidden | No custody/credential authority in this field purpose. Never include credentials in a browser DTO. |
| Other Alpha versions/researchers, members, grants, parent grants/native proofs, field-seal preimages | Hidden | Self slice is neither a directory nor a policy audit endpoint. |
| Raw strategy code/parameters/artifacts | No new Execution disclosure | Governed by the original Research/artifact reader and exact current permissions, not copied into Manager metadata. |
| Promotion/archive/reactivate/fund/recall/Live controls | Not granted | Separate exact action, SoD, step-up, preview, source capability and command commissioning remain mandatory. |
| Decider/creator actor names and roles | Hidden unless a separate finite reviewed audit purpose exists | Do not infer SoD eligibility from ownership or recorded UI labels. |

## Implementation / acceptance after Bobby's decision

1. Record the approved finite keys and semantics in a versioned manifest; retain
   the existing policy revision history. No wildcard or broad owner shortcut.
2. Define a distinct typed own-slice contract, generated type and sparse fixture;
   explicit absence for unrecorded source facts, not zero or derived labels.
3. Enforce own/other researcher, wrong version/workspace/environment, independent
   Portfolio/account rights, DENY/delegation/revoke and after-await settlement.
4. Negative query/search/count/export/cursor/stream tests must not reveal fields
   excluded by this matrix. Authorize all ends of linked reads independently.
5. Claude consumes only the approved published contract, preserves the reviewed
   UI and records actual browser/consumer acceptance separately.

Current producer support for self eligibility/navigation does not implement
this field matrix. The outstanding Bobby decision is this matrix, not the
already-decided Score formula or current-only Manager query policy.
