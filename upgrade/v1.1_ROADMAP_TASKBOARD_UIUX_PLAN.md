## 1. Bối cảnh & mục tiêu

Version 1 đã chạy được end-to-end (data historical thật qua installed package
`primus-historical-market-data==0.1.0rc3` — runtime không bao giờ `sys.path`
import source checkout; cài qua pip nội bộ, mount read-only). Phần còn yếu là
trải nghiệm Roadmap + Task Board. Mục tiêu slice này: **hai màn đó hoàn thiện,
đẹp, flow chuẩn nhất trong version 1.1** — kèm 1 webhook thông báo khi kéo task.

## 3. Task Board màn — yêu cầu

1. **Font chữ lộn xộn** → thống nhất bộ typography từ design tokens (v0.4
   §26), không style lẻ, không font mặc định lệch.
2. **Tick box (checkbox) xấu, có phần dùng mặc định hệ thống** → custom
   checkbox component trong design system (đủ trạng thái: checked/unchecked/
   indeterminate/disabled/loading), không dùng native mặc định.
3. **Tính năng phải tốt hơn**: cập nhật task đầy đủ (title, owner,
   workstream, status, position), undo/redo hoặc confirm khi kéo, activity
   history hiển thị được (endpoint đã có), filter/group theo workstream/
   owner/status, đếm task theo cột.
4. **UI khá ổn — flow chưa hay**: sáng tạo lại luồng kéo thả (drag → drop →
   optimistic update → rollback nếu lỗi), transition rõ ràng, phản hồi
   trực quan khi thay đổi trạng thái. Báo về webhook khi kéo (xem §5).

## 5. Webhook báo khi kéo task — đã xong (backend)

- Khi kéo task trong Task Board (drag → đổi cột = gọi transition/move endpoint
  hiện có), backend enqueue thông báo vào outbox rồi gửi tới **Lark bot**
  (Feishu) kèm chữ ký HMAC-SHA256 (timestamp + secret).
- Cấu hình qua env `LARK_WEBHOOK_URL` + `LARK_WEBHOOK_SIGN_SECRET` +
  `PORTAL_NOTIFY_CHANNELS=discord,lark` — **secret chỉ ở env server (.env
  gitignored), không được commit/lộ ra UI hay log**. Payload không chứa secret.
- Frontend chỉ cần: sau khi kéo thành công hiện thông báo nhỏ "Đã gửi thông
  báo" (nếu muốn) — backend tự lo delivery + retry.
- **Không hard-code URL/secret ở frontend**; không log nội dung webhook URL.
