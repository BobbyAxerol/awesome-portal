## 1. Goal and scope

BAR-02 freezes the current compatibility boundaries before the mother shell
embeds QuantBT Research and Planning. It delivers:

- Golden contract snapshots (Portal API OpenAPI, Planning API OpenAPI, run
  request JSON Schema) with a digest manifest.
- Additive-only compatibility metadata: every Portal-written JSON artifact
  gains `artifact_schema_version` and `producer` provenance.
- A validated versioned cross-link sidecar (`portal.links.v1`) for the U05
  feature/screen/concern ↔ epic/task/Figma/repository mapping.
- Defined legacy-route and future façade adapter rules, without dual-writing
  state.

It does not change QuantBT/Planning authority, the protected strategy kernel,
the engine-owned `manifest.json`, or existing Planning state.

## 2. Decisions locked by this deep dive

1. **Snapshots are the parity freeze.** `upgrade/backend/bar02/snapshots/`
   holds the committed Portal API OpenAPI, Planning API OpenAPI and run
   request JSON Schema with a sha256 digest manifest. CI regenerates and
   compares them; a drift is a breaking-change review, not a silent update.
2. **Existing output changes only additively.** The engine-owned
   `manifest.json` (which already carries `artifact_schema_version` and
   `portal_version`) stays byte-exact. Portal-written JSON artifacts
   (`status.json`, `config/request.json`, `config/fold_plan.json`,
   `config.json`, `strategy.json`, `metrics.json`, `selection/*.json`,
   `wfo/params_by_fold.json`) gain exactly two additive top-level fields:
   `artifact_schema_version` (string, currently `"1"`) and `producer`
   (`{"service": "portal-api", "artifact": "<artifact>", "version": "<portal
   version>"}`). No existing key changes, is removed or is reordered
   semantically.
3. **Services stay private and unchanged in authority.** Compose exposes only
   the web gateway port; the nginx gateway keeps the `/roadmap-task-board/`
   and `/api/` compatibility proxies. Portal API never imports Planning
   repository code or opens its SQLite.
4. **The cross-link sidecar is a temporary validated overlay, not a second
   registry.** `registry/links.v1.json` references registry feature/screen/
   concern IDs and adds Planning-side links (`roadmap_epic_id`,
   `planning_task_ids`, `figma_frame_id`, `repository_scope`,
   `prototype_route`, `activation_gate`). It validates against
   `portal-links.v1.schema.json` and cross-checks registry references at
   startup; invalid links fail readiness like an invalid registry. It migrates
   into Planning/PostgreSQL authority in later phases; until then it is
   read-only.
5. **Legacy routes stay data, not code.** Registry `legacy_routes` remain the
   validated source for legacy-path redirects; the gateway keeps its current
   compatibility locations. No route handler learns new hard-coded paths and
   no façade dual-writes state: the BAR-01 summary adapters remain read-only
   strangler seams toward the future U10 Control API façade.
6. **Parity gates stay green.** Protected strategy hash, golden kernel parity,
   full backend/frontend suites and Planning state tests must pass unchanged
   except for the documented additive fields.

## 4. Artifact provenance contract (additive)

Every JSON artifact written by Portal code (list in §2.2) carries:

```json
{
  "artifact_schema_version": "1",
  "producer": {
    "service": "portal-api",
    "artifact": "status.json",
    "version": "0.1.0"
  }
}
```

Rules:

- Fields are added at write time by `with_portal_provenance`; readers ignore
  unknown keys by contract.
- `artifact_schema_version` changes only with an intentional additive/breaking
  change review of that artifact family.
- The engine-owned `manifest.json` keeps its own existing
  `artifact_schema_version`/`portal_version` fields; Portal does not rewrite
  them.

## 5. Cross-link sidecar contract (`portal.links.v1`)

```ts
interface PortalLinksV1 {
  schema_version: "portal.links.v1";
  links_revision: number;
  reviewed_at: string;
  entries: PortalLinkEntryV1[];
}

interface PortalLinkEntryV1 {
  id: string;
  feature_id: string | null;
  screen_id: string | null;
  concern_id: string | null;
  roadmap_epic_id: string | null;
  planning_task_ids: string[];
  figma_frame_id: string | null;
  repository_scope: string[];
  prototype_route: string | null;
  activation_gate: string | null;
}
```

Validation invariants (fail startup/readiness):

- At least one of `feature_id`/`screen_id`/`concern_id` is present; each
  references an existing registry entity.
- IDs match the registry stable-ID or Planning safe-ID patterns; no
  duplicates per entity type; `prototype_route` is a safe registry-style
  route; no secret/path/host metadata.
- `planning_task_ids` entries are Planning-safe IDs; external existence
  checking against the Planning API waits for U05 proper — unmapped links
  appear as such in the response integrity block, never invented.

Read-only endpoint: `GET /api/v1/portal/links` returns the sidecar plus an
`integrity` block (entity coverage counts and `validated_at`). Headers follow
the registry contract (`ETag`, `no-cache, must-revalidate`, `Vary:
Authorization, Cookie`, `If-None-Match` → 304).

## 6. Legacy-route and façade rules

- Registry `legacy_routes` (e.g. QuantBT `/runs`, `/overview`, …; Planning
  `/roadmap-task-board/`) are the validated redirect data. Add a legacy alias
  only through registry data plus a gateway/route compatibility test.
- The gateway keeps `/roadmap-task-board/` and `/api/` proxies until U10.
- The future TypeScript façade reuses the BAR-01 adapter seam; no BAR-02 code
  writes to QuantBT or Planning state and no summary/registry route gains a
  mutation verb.

## 7. Non-goals

- No PostgreSQL/NATS/MinIO/Redis, no identity, no workspace authority.
- No frontend shell visuals; no gateway topology change.
- No Planning SQLite migration and no task-existence sync in this slice.

## 8. Exit evidence

BAR-02 is complete when: snapshots and digest manifest regenerate
byte-identical; provenance fields are additive with golden-field parity tests;
the links sidecar validates and serves with integrity metadata; legacy/façade
parity tests pass; protected hash, Planning state and all existing suites stay
green; and every coherent slice is committed.
