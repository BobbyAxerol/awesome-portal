# CG-FG-S03-02 / CG-FG-S04-01 — shared claim projection

Status: backend candidate; exact-HEAD preview and full hook pending at this
checkpoint. No frontend, production runtime or source system was changed.

One Control API projector now reads the exact current Atlas mode × schedule
for a run-bound release and, only after completion, the workspace-scoped
immutable current-source seal. Progress S03 receives four typed methodology
facts. Evidence Hub S04 receives those same four facts plus holdout state,
execution contract and runtime authority in its seven-cell order. `ISSUED`
requires the matching sealed QuantBT fact; the P04 singular progress claim
never becomes four invented issued claims. An old/historical release or missing
source fact returns `NOT_PUBLISHED` or remains explicitly `FORECAST`.

For current WFO, the no-holdout profile returns `NOT_APPLICABLE`; a P04 Hub
cannot prove the P08 holdout seal from its own row and returns
`P04_HOLDOUT_SEAL_NOT_IN_EVIDENCE_HUB`. A current Atlas route may forecast its
execution contract, but it cannot attest runtime authority; that stays typed
absent until a sealed source fact exists. The existing singular claim and
methodology certificate are unchanged.

The same generated `MethodologyClaim` discriminated union is published in
`research-progress.d.ts` (`ProgressRead.claims`, 4) and
`research-evidence.d.ts` (`EvidenceHub.claims`, 7). Both are additive optional
fields for rolling-deploy compatibility; current authenticated HTTP reads
emit them. SSE's compact synchronous read frame may omit them, so S03 must
retain its existing snapshot fallback. Source reads stay server-side; no
relation, seal or credential is browser-selectable. Atlas is cached per
principal/role for 30 seconds, max 128 entries; source facts are never cached
or used as an authorization cache.

Unit source: repository-pinned Atlas fixture and a real QuantBT 1.1.1 WFO
seal fixture. The four facts are FORECAST before seal and ISSUED after seal;
the S04 strip has seven entries, with P04-only absences typed. Contract
fixtures cover both states, generated clients and invalid ISSUED/null text.

Claude handoff: bind S03/S04 to the new `claims` array, without parsing the
singular claim's prose or changing approved visuals. Display state and
reason per cell; never turn a FORECAST into an ISSUED badge. Browser/HiFi
receipt remains frontend-owned.
