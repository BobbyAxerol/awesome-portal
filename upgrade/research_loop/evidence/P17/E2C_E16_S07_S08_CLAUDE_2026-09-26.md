**Three decisions worth naming.**

- **D-E2c-1 — the chain computes nothing.** No digest is recomputed, none is combined with
  another, and no link is inferred from a sibling. Each row carries its own `source_key` in the
  title, so a reader can say which field produced the value on screen.
- **D-E2c-2 — the engine pin is absent on the hub, and says so.** The P04 freeze response
  (`research.freeze-detail.v1`) has no engine field. The engine release is inside the adapter
  contract digest the last link prints, but the version *string* is not published by this read, so
  the link states that instead of restating `1.1.1` from a build constant or borrowing the retained
  lane's value. Serving it would be a contract change on a row the ledger scopes as frontend; the
  request is recorded in §6 (E16-R2) rather than taken.
- **D-E2c-3 — the params-digest link does not borrow F4's identity rule.** On the P04 lane
  `sealed_params_sha256` *is* the F4 sealed-params row, so the served rule
  (`SHA256_CANONICAL_PARAMETER_MAP_V1`) names it exactly. On the retained lane F4 compares
  QuantBT's **candidate id** and the digest is the sha256 beside it — labelling a sha256 "QuantBT
  candidate id" would be a small lie, so the link falls back to the contract's own description of
  the field. `paramsDigestRule()` in `DigestChain.tsx` makes the choice; a test pins it.

- **Verify stays one control.** The HiFi puts `VERIFY DIGEST` on F3 and has no custody card; the
  portal has both. Rather than ship two buttons for one POST, F3 carries the HiFi's label plus the
  scope sentence and the button stays with the receipt. A test asserts exactly one
  `[data-action='verify']` on the screen and no `<button>` inside the chain.

### 2.2 Row 8.5 — the IS / OOS / HOLDOUT band (HiFi `QuantBT 08 S4 Execute Replay.dc.html`, offset 18000)

Component: `apps/portal/frontend/src/research/SplitBand.tsx`. It replaces the text line

| HiFi band | Field (P04 hub) | Field (RS-02 retained) | States | Test |
|---|---|---|---|---|
| `IS` (hatched) | `windows.is` from `researchSplitDetailGetV1` | active fold's `train_start_utc_ms` → `train_end_utc_ms` from `researchCurrentSourceSplitGetV1` | AVAILABLE · NOT_PUBLISHED · NOT_ASSERTED · NOT_APPLICABLE | `executeReplay` "shades IS, the plotted OOS…"; `executeCandleReplay` "shades IS and the plotted OOS…" |
| `OOS (plotted)` (solid) | `windows.outer_oos` | active fold's `test_start_utc_ms` → `test_end_utc_ms` | same | same |
| `HOLDOUT` (hatched, dashed) | `windows.holdout` | **no span published** — the claim strip's `holdout` fact verbatim | AVAILABLE (hub) · NOT_APPLICABLE (retained WFO: `P10_DELTA_WFO_PROFILE_HAS_NO_HOLDOUT_SEGMENT`) · NOT_PUBLISHED | `executeCandleReplay` "a profile with no holdout segment says not applicable…"; `executeReplay` "a window P14 did not publish…" |
| between two published windows | — | — | a drawn gap | `executeCandleReplay` "draws the gap … never closed up" |

**Decisions.**

- **D-E2c-4 — width is the published duration and nothing else.** Each band's `flex-grow` is
  `end_exclusive_utc_ms − start_utc_ms`. The HiFi's 2.2 / 1 / 0.7 ratios are its demo cast; on the
  real WFO fold the ratio is 720 : 168 bars and the OOS band is correspondingly narrow. Tests
  assert the exact millisecond widths.
- **D-E2c-5 — a gap is drawn as a gap.** The real fold's train window ends one bar before its test
  window starts. Closing that up would assert coverage the server never published, so a dotted
  spacer of exactly the gap's duration sits between them.
- **D-E2c-6 — an unpublished window gets no width at all.** It keeps its label, says "not
  published" or "not applicable", and carries the server's reason in the title. A zero-width or
  dash-filled band would read as "this window is tiny", not "this window is not published".
- **D-E2c-7 — the read belongs to the route.** One bounded read on arrival of whichever lane
  answered, and none when the fold changes (the fold plan already holds every fold). It waits for
  a lane to answer first: asked at t=0 the lane still reads `hub` for every run, so a walk-forward
  run would otherwise read the P04 hub split and then its own fold plan — two reads for one band.
  A test asserts the retained lane never reads `/split`.
- **D-E2c-8 — the in-sample label takes the soft ink, not `--role-is`.** `--role-is` (`#7a8699`)
  measures 3.68:1 on paper, below AA, and axe flagged it. The swatch keeps the role tone; the word
  does not need it, and muting IS also reads correctly, since IS is the window this chart does not
  plot. `--role-oos` and `--role-holdout` both pass and keep their colour.

## 6. E16 · the P04 replay candles — why they cannot be served, and the source request

### 6.1 What was checked

W5b gave the WFO retained lane candles by retaining the run's own analysed bars at seal time
(decision D1 in [`W5B_REPLAY_CLAUDE_2026-09-25.md`](W5B_REPLAY_CLAUDE_2026-09-25.md)) and
re-exporting them: `advanced_walkforward_runner.py:600-633` writes `series/stitched.parquet` with
OHLCV, `research_run_producer.py:685-689` copies the whole directory into the artifact root, and
`current_source_artifacts.py:1028-1139` (`_attach_bar_ledger`) turns each bar into a
`research.current-source-bar.v1` block inside the observation payload. **It needed no DDL** — the
block rides in the pre-existing `research.current_source_rows_v1.payload` jsonb.

The question for E16 was whether the P04 hub lane has the same material. It does not.

### 6.2 The decisive finding

**The P04 child reads OHLC and then deletes the tape before the artifact bundle is written.**

`apps/portal/backend/src/portal_api/services/research_run_producer.py:470-475`:

```python
finally:
    # This tape is a short-lived derived work input, not a second
    # historical store. Its stable identity is the P08 digest retained
    # by Control API; source rows never remain under worker scratch.
    if job_directory.exists():
        shutil.rmtree(job_directory)
```

The bundle is created afterwards, at `:477`. The bars live in
`job_directory / "is_oos_only.parquet"` (`:376-377`), are read by the child at
`workers/research_child.py:465-466`, and are gone by `:477`.

**The whole persisted P04 artifact set** is two JSON files: `config/request.json` and
`research/p10-receipt.json` (`research_run_producer.py:486-554`). There is no `series/` directory
and no parquet. So there is no P04 equivalent of W5b's move — nothing to re-export.

### 6.3 Three further walls, each independent

| Wall | Evidence |
|---|---|
| The child returns scalars and derived series only | `research_child.py:477-483`, `:332-393`; `bars` is a **count string** (`:375`). The docstring at `:277-283` says the evidence source *"intentionally excludes OHLCV/source rows, fills, benchmark and funding because P04 does not publish those facts through this adapter."* |
| The receipt has no room | `_MAX_EVIDENCE_RECEIPT_BYTES = 24 KiB` against a 28 KiB ingress ceiling (`research_child.py:43-54`); the four existing series already consume it. A 2,928-bar OHLC series cannot fit; only a bucketed overview could, and only after rebalancing the existing caps. |

### 6.4 Source / engine requests

**E16-R1 — retain a bounded OHLC overview on the P04 run (source: Portal backend P10 producer + P06 child).**

- *Need:* S08 on a P04 run draws equity samples with no price context; HiFi 08 draws candles.
- *Locator:* `research_run_producer.py:376-377` (the tape), `:470-475` (the delete), `:477-554`
  (the bundle); `research_child.py:277-408` (`_p13_evidence_source`).
- *Actual:* the tape is deleted before the bundle is written; the receipt carries a bar **count**.
- *Smallest change that would be true:* compute the `_candle_overview` shape (≤160 buckets, true
  bucket extrema, `bucket_bars` in the caption) **inside the child, while it still holds `market`**,
  and carry it in the receipt. That keeps the A08/A09 rule (a GET never re-opens HMD or QuantBT)
  and matches W5b D8.
- *Blocked on:* the 24 KiB receipt budget (`research_child.py:54`). The four existing series
  already consume it, so this needs the caps rebalanced or a second bounded channel.
- *Storage:* prefer the existing `projection` jsonb (no DDL, mirroring how W5b added candles with
  zero DDL) over a new `series_kind`, which would need a migration and a CHECK change.
- *Hard limit to state plainly:* **only new runs could ever gain this.** Existing P04 runs have no
  retained bars and never will from their own artifacts. Any backfill would have to re-read the P08
  snapshot (`migrations/1723680000043…sql:66-68` keeps `snapshot_id` + `snapshot_content_hash`),
  which is deliberately not in the artifact bundle (`research_run_producer.py:481-485`) and is a
  separate, heavier design — not a shortcut.
- *Until then:* the typed absence stands, and S08 says so in English.

**E16-R2 — publish the engine pin on the P04 freeze read (owner: Claude, ≤P21; not taken here).**

- *Need:* F3's engine-pin link is the only one the hub lane cannot fill (§2.1, D-E2c-2).
- *Actual:* `research.freeze-detail.v1` `provenance` has no engine field.
- *Available:* the run's historical binding already holds it —
  `P04_DELTA_DECLARED_CONTRACT.execution.engine_release_id = "er_quantbt_111"` and
  `P04_DELTA_BINDING.dependencyRef = "portal.p04.delta-rsi:quantbt-engine==1.1.1"`
  (`p04-delta.binding.ts:56`, `:101`), looked up by the run's exact adapter digest.
- *Smallest change:* add `engine_pin` (value + its source key) to `ParameterAuthoritySchema`
  (`stage4-binding.ts:95`), which both lanes already serve, plus the OpenAPI/zod regeneration,
  fixtures and a service test. No migration — the binding is already in code.
- *Why not now:* the ledger scopes 7.9 as frontend, and the chain is honest without it. Held for
  Bobby or a following slice.
