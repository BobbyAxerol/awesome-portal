## 3. DR-03 decision (D-W6B-01)

Guide DR-03: *VERIFY_SOURCE P02/P19 with unchanged governance; if the source lacks the field/relation, the owner fixes a research-only representation; never pick a best or add an execution uniqueness policy.* Verified sources today: QuantBT publishes no promotion fact; P21 seals a Portal-local release candidate that its own contract declares is **neither delivery nor approval**; P22 (Codex) owns the downstream publish/approval.

Decision:
1. The only authority that may write `research.attempt_promotion_pick_facts_v1` is a governed **approval of a sealed release candidate** (P22). The table's immutability, same-version trigger and "runtime SELECT only" stay; P22 gets a reviewed insert identity when it lands (handoff to Codex, not built here — `release-candidate*` / `publication*` are Codex's).
2. Until then the pick is a typed absence with its authority named (`source_authority.state = NOT_CONNECTED`), and the screen says so beside the banner.
3. The research-only representation of "this attempt is going forward" is the **rc chip** (a sealed pack or the viewer's draft), shown per attempt and never called a pick. No newest/ACTIVE/metric/rc-derived pick and no uniqueness policy.
4. Exit gate "DR03 resolved for mandatory field": resolved as a typed, sourced absence with a named writer.

## 4. Other decisions

- **D-W6B-02 presentation rule v1.** STORIED when any of: the version's published pick; an rc relation; the version's chronologically first attempt (whole history, not the page); a version change (gates reset); ≥2 changed *declared* keys (requested-spec keys only, so one seed change is not counted twice through its effective echo). Everything else is a PROBE. Spec §14's "được đánh dấu" has no source and is not invented. On the preview's real alpha this gives 1 storied + 28 probes: the 28 are root re-runs without a parent — honest.
- **D-W6B-03 paging.** Newest window + older cursor instead of oldest-first, so ACTIVE work is never cut off. The cursor has no TTL on purpose: attempts are append-only, and a deterministic token can sit inside the revalidated body (a TTL token would change the ETag every read).
- **D-W6B-04 metrics.** One mapping for 01 and 10 (`ResearchRunLibraryService.mapRow` made public; its SQL shared as static helpers) so the screens cannot disagree. The RS-02 fallback is labelled (`selected trial, mean of folds`) and never mixed with a P13 value. FE formats ratios with `researchFormat.formatMetric(…, "ratio")` (3 decimals), exact string in `title` / `data-metric-value`.
- **D-W6B-05 untried.** Hi-fi has one untried row per alpha: S10 shows the ACTIVE version's list. DEFERRED Atlas routes are not "untried" (they cannot run). An unreadable Atlas is `P19_ENGINE_ATLAS_NOT_READABLE`, never a failed lineage.
- **D-W6B-06 version outcome words.** `best cert X` uses the certificate *grade* the source issued (a governance ordinal, not a metric); `promote closed` for SUPERSEDED/ABANDONED; `rc sealed / rc_ draft / no rc`; `pick <att> / no pick published`. PARTIAL when the page is bounded.
- **D-W6B-07 telemetry** — §2.
- **D-W6B-08 "the ACTIVE attempt".** The filter chip ACTIVE stays version-level (hi-fi, VD-P19-01); the promotion rule stays verbatim; "the ACTIVE attempt that promotes" is the PICKED one, which only a published pick names. Standing line: `awaiting a published pick 13 · promotion closed 16` on real data.
- **D-W6B-09 compatibility.** The preview still serves contract 1.0 (not rebuilt, per mandate). `normalizeLineage` turns each missing 1.1 field into a typed absence (`P19_SERVER_PREDATES_LINEAGE_CONTRACT_1_1`); the 52 original S10 tests now run as the pre-1.1 suite.
- **D-W6B-10 axe / hi-fi deviation.** axe on real data flagged amber/green text on tinted grounds (hi-fi colours: `.ln-pick .t`, rule heading, pressed probe toggle/chip, ACTIVE chip on the selected row). Without touching tokens, those labels now sit on `--paper-raised` (pressed toggle/chip: white ground instead of the hi-fi's pale amber; rule heading: a white label pill). Same for rc, cert and picked chips.
