### The flake run 4 caught, and why it was a real defect in the cell

`E20 S14 … at mobile` failed reading the gate rows: it expected the seven served gates and got
`[]`. The screen is right and the cell was wrong. While the one gates request is in flight, S14
honestly draws **seven `RUNNING` rows** (CG-P07-04: one synchronous request, so no row may claim to
have finished early); when the answer lands, `GateList` replaces them and reveals the real rows with
a 120 ms stagger **starting from zero**. So `toHaveCount(7)` can be satisfied by the RUNNING
placeholders, and the single `evaluateAll` that followed can land in the empty moment between the
two lists. Run 3 won that race; run 4 lost it.

Fixed by reading the settled value rather than a single frame: the gate triples, the stepper's four
progress states and the mirror rows are now asserted with `expect.poll`, and the S00 card list and
S08 sample ledger settle on the server's id list before being snapshotted. **No assertion was
weakened** — the same exact arrays are compared; they are simply compared against the DOM once it
has stopped moving. `--repeat-each=3` on the three cells then passed 18/18.

**The cells were checked for bite, not only for green.** Three failures were produced on purpose or
by accident and all three were real:

1. asserting `revision 3` on Screen 00 failed, because the screen does not print it (finding 1
   below) — the first draft was wrong, not the screen;
2. asserting the candle absence was *visible* failed, because it sits behind a closed disclosure —
   the cell now opens it, which is what a reader would have to do;
3. a deliberate mutation — emptying `JOURNEY_UNROUTED_KEYS` — failed the S00 cell on exactly
   `"alpha-version"`, so the badge column really is compared card by card and a wrongly-pinned key
   cannot pass.

Per cell: S00 laptop/mobile, S14 laptop/mobile, S08-P04 laptop/mobile — 6 new, 0 skipped,
0 flaky. No existing cell was touched: the diff is additive (one appended block).

## What could not be asserted honestly

1. **The descriptor revision number is not on screen.** `JourneyMap` passes the revision as a
   panel `meta` prop to a `ResearchPanel` with `variant="plain"`, and
   `ResearchPanel` renders its header — and therefore `meta` — only when `variant === "framed"`
   (`ResearchPanel.tsx:173`). The first draft asserted `revision 3` and failed: the string is
   nowhere in the screen's text. Rather than weaken it, the cell pins the descriptor identity
   through the sr-only `[data-descriptor-digest]` line, which carries `content_sha256`
   `7f42203c4f6b4f326e28e020398a530c2fe6268c05352eb9aab5b918e5cd548d` — the exact value migration
   067 registered for revision 3, so it identifies the revision uniquely. **Open:** decide whether
   Screen 00 should print the revision (a one-word change: `variant="framed"`, or move the meta into
   the header the screen already draws). Not changed here, because the preview serves the bundle
   built at `c81e8dc2` and a frontend change would not be visible to this lane.

2. **One card the descriptor calls built has no route in this build.** Descriptor revision 3
   publishes `13 · Alpha version` (`card_id: alpha-version`, `target_kind: SHIPPED`,
   `target_key: alpha_version_legacy`) as `AVAILABLE`; `screenRoutes.ts` has no entry for
   `alpha_version_legacy`, so the card draws `NOT ROUTED` — correctly, per `unreachableReason`'s
   rule that a deployment gap must not be dressed as a roadmap gap. The cell does **not** excuse
   this with a loosened check: `JOURNEY_UNROUTED_KEYS` pins the key by name and the badge column is
   compared as a whole, so a *second* unrouted card fails the lane, and routing this one fails it
   too (the pin must then be removed). **Open:** either map `alpha_version_legacy` to the shipped
   screen it means, or publish descriptor revision 4 with that card `PLANNED`. It is a shipped-side
   card, not a Research screen, so it is a naming decision rather than a build gap.

3. **S14's writes are not real.** Parse, gates, register and activate are answered in the browser
   with the contract fixtures, because the preview is read-only. The cell proves the preview was
   *not* written to; it does not prove the server would accept the same sequence. That is E6's
   "left open #3" — a real-backend browser receipt for the S14 write path needs a writable stack —
   and OL-01 still blocks running an imported version at all.

4. **The route sweep's own failures are recorded, not asserted.** The 21 destinations include three
   outside Research (`/`, `/portal-map`, `/administration/profile-access`). The sweep asserts they
   are mounted and that it reached no `/internal/` route, and writes its full request/console log
   into the receipt; it does not assert those shipped screens are error-free, which is not this
   lane's subject. Observed clean on both runs.

## Follow-up, 2026-09-27 — the two decisions this record asked for

Both were answered rather than left open.

**1. S00 never printed the descriptor revision.** `ResearchPanel` renders `meta` only in its
framed variant and this screen is plain, so the map said which screens exist without saying
which published answer it was reading. The screen now prints `descriptor revision N` in its
header (`data-descriptor-revision`), beside the legend. The sr-only digest stays.

**2. `alpha_version_legacy` drew NOT ROUTED.** The screen it names is mounted
(`alphas/:alphaId/:version`); what the journey map lacks is an Alpha and a version, which is
exactly the D2 case, not an unbuilt screen. Calling it PLANNED in a revision 4 would have been
false. It now goes through the same Run Library picker as the other context-scoped cards, and
resolves against the chosen row's binding (`alpha_id` + `alpha_version_id`); a row that names no
version still cannot address it and says so. `JOURNEY_UNROUTED_KEYS` is therefore **empty**, so
any card that draws NOT ROUTED now fails the lane.
