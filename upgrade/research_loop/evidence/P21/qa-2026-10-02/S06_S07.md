## 3. UX defects

Severity: high / medium / low. Steps assume WFO23 unless said.

**D1 (high) Keyboard: 400 tab stops in A2 + 100 in the ledger.** Steps: focus `Evidence Flow` breadcrumb, press Tab until `S3 Freeze →` in B1: 432 presses. Arrow keys do nothing between points (Enter selects). Shots 86. Fix: one tab stop for the plot (roving tabindex, arrows move to nearest point), ledger rows `tabindex=-1` with arrow navigation, or an "A2 as table" skip. File: SearchSurface.tsx:198 (`data-surface-point` button), SearchDetail.tsx ledger row button (~832).

**D2 (medium-high) "frozen at" is the Stage-4 completion event, shown next to "pool closes before OOS".** `pool.frozen_at_source = "P11_STAGE_COMPLETED_S4_EVENT"`; value equals the page's as-of (13:44:51 UTC). It is tooltip-only (SearchStageB.tsx:156-170, comment at :148 admits it). A reader takes it as the pool freeze moment; it is after OOS was read. Fix: label "stage 4 completed" or hide until the engine publishes the real freeze clock (see inventory B3).

**D3 (medium-high) Two different "params digest" values on S07.** WFO23: Frozen θ* header `params digest a7487281` (= `sha256:a74872817bf1…`, F3 row "params digest") vs F4 "sealed params digest `00b18de5ca92…`" and ordering rows "OOS child = frozen θ* · 00b18de5ca92". The API says why (`stage4_binding.sealed_params_sha256` vs row `identity_rule QUANTBT_WALKFORWARD_STRATEGY_CANDIDATE_ID_V1`: the second is the engine candidate id, not a sha256), but the label is the same. Shots 34, 35, 36. Fix: label the second "candidate id (engine)" and never call it a params digest. File: Stage4Binding.tsx (row labels from server `label`) — ask backend to send `label: "frozen candidate id"` (see request R-S07-3).

**D4 (medium) Float noise in the trial ledger.** 30 values on WFO23, e.g. `rvol=2.4000000000000004`, `slpercent=0.8999999999999999`, `1.9000000000000001`, also in trial aria-labels (`rvol 2.4000000000`). Backend: parameters are strings from Optuna floats; round at the portal serializer (request R-S06-3).

**D5 (medium-high) Ledger and point tooltips cover only 100 of 400 trials.** `ledger.page.has_more=true, next_cursor` is served; the UI never pages. Shots 12, 28. Fix: FE "load more"/auto page with the cursor (FE-GAP); ask backend for `surface.points[].parameters` so tooltips need no ledger (R-S06-2). File: SearchDetail.tsx ledger fetch (`useFoldLedger`), SearchSurface.tsx tooltip.
