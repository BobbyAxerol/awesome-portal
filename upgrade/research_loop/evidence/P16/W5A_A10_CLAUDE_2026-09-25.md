## 2. Decisions

### DR-02: one bound-warning definition for S06 and S07

- Server vocabulary `research.bound-warning.v1` lives in `apps/control-api/src/research/bound-warning.ts`, with copy `research.bound-warning-copy.v1`.
  Search (S06) and Freeze (S07) both publish it, and the FE has one renderer (`BoundWarningNote` in `BoundWarning.tsx`).
- Reference space: the DECLARED_RANGE of the parameter. The position is computed with exact BigInt decimals, not floats.
- Levels (inclusive): `AT_BOUND` ≤6% or ≥94%, `NEAR_BOUND` ≤18% or ≥82%, otherwise `NONE`.
- `NOT_APPLICABLE` is typed with a reason: `ZERO_WIDTH`, `CATEGORICAL`, `OUTSIDE`, `NOT_EXACT_DECIMAL`, `RANGE_NOT_PUBLISHED`, `INVERTED`.
- The Freeze HiFi's "one step / 12% / 88%" rule is retired. Two different rules on two screens for the same θ* would contradict each other.
- The copy is guide §9.4's safe sentence: "Selected value is near a configured boundary; review sensitivity and declared bounds."
  The FE prints the server's exact `position_percent` and never recomputes it.
- An older server that publishes no warning renders "warning not published". This was found in the browser (P04 run on the preview server), where it had blanked the page.

### A10b: historical parameter binding

- `ResearchParameterBindingRegistry` resolves the parameter binding by the exact adapter digest (P04) or WFO profile digest.
- An unregistered digest fails closed. `P04_ADAPTER_CONTRACT` returns MISMATCH against the newest registered digest, and the freeze is BLOCKED.
  The bundle check reports `NOT_PUBLISHED` / `P16_HISTORICAL_PARAMETER_BINDING_NOT_REGISTERED`.
  The newest binding is never silently used for an old run.

### A10a: expected-artifact-byte verification

- A private observer, `POST /internal/research/artifacts/observe`, runs in the portal backend under principal method `research_artifact_verify`.
  It reads only under `PORTAL_RESEARCH_RETAINED_ROOT` (default `PORTAL_ARTIFACT_ROOT/durable-store/research-retained`) and returns observed digests.
  It does no comparison and makes no decision.
- Control-api compares the observed digests with `research.artifacts.manifest_digest` and `artifact_parts.part_digest`, which were sealed at P05.
  Documents are checked against the digests recorded in the manifest.
- The receipt is written to `research.artifact_byte_receipts_v1`, which is immutable (append-only). The insert trigger requires `expected` = the seal's manifest digest.
  A re-verify can therefore never rebaseline the expected digest from wrong bytes (T04).
- **I decided not to** move the P05 artifact state to CORRUPT. That lifecycle is one-way, and it would forbid spec §4's
  "re-verify after repair". The receipt is the quarantine record instead.
  - When the latest receipt is MISMATCH or MISSING: hub integrity is BLOCKED, the frozen table is empty, and the ETag moves.
  - When the bytes are restored, a new MATCH receipt unblocks the freeze.
- When the observer is unavailable the result is UNAVAILABLE and nothing is recorded, so an outage never becomes a proof.
- Scope labels: `PORTAL_RETAINED_DIGEST_BINDING_AND_P05_ARTIFACT_BYTES` / `P05_ARTIFACT_BYTES_ONLY`.
  The result is `PARTIAL_MATCH`, never "chain intact".
- Flag: `FEATURE_RESEARCH_ARTIFACT_BYTE_VERIFY`.

### A10c: what-if grid (Screen 07)

- **Axes.** HiFi's `entry_z` maps to Delta `rvol` (1–2.5, step 0.1), and `atr_mult` maps to `slpercent` (0.7–2.5, step 0.1).
  These are the only two continuous Delta parameters with the same roles (entry threshold and stop distance).
- **Grid shape.** 9×9 = θ* ± 4 declared steps, clamped at the declaration.
  Clamped cells share one canonical evaluation, the unclamped node. Nothing is interpolated.
- **Evaluation key.** `sha256{profile digest, objective, parameters, dataset_binding_digest, requested_spec_digest, engine_release_id, random_seed}`.
  - Profile: `p16.delta-whatif-grid.v1`, digest `3c29160abf214a0ef1c20c630048442ef131aadc1d00849f69ae428d0ff513bc`.
  - The profile is pinned in both TS and Python twins, which must agree.
- **Read path.** A cell is filled only from an exact existing evaluation. Every other cell is typed `MISSING` and never shows 0.
  The read exposes `what_if{sliders, grid, coverage "n / 81", job}`.
  GET, mount and slider moves never create a job (verified in unit tests and the browser probe).
- **Explicit compute.** "evaluate grid" creates ONE bounded diagnostic job.
  - The job is its own DIAGNOSTIC attempt, whose `parent_attempt_id` is the parent's.
  - The run is a `DIAGNOSTIC_OF_RUN` run. The job is a BACKGROUND DIAGNOSTIC job with `attempt_limit` 1.
  - The producer intent is DIAGNOSTIC and keeps the parent's actor and preflight (FK).
  - One job may be in flight per parent. Requests are deduped by grid key (a replay returns the same job), and a retry after failure gets a new ordinal.
  - The job asks only for the missing unique evaluations (≤81). Admission, CSRF, audit, P11 progress and cancel reuse the existing lanes.
- **Worker.** A P06 isolated child enqueues the configurations as fixed Optuna trials inside the parent's exact WFO request.
  QuantBT's own objective scores them, so θ* re-scores to exactly the parent's J.
  - Results are sealed as P05 `whatif_results` plus a `WHATIF_GRID` relation before `run_completed`.
  - The reports sidecar is skipped. CPU cap is 120 s, wall cap 240 s.
- **Lineage.** DIAGNOSTIC attempts are hidden. The diagnostic run is listed as a child run of the parent attempt.
- **Honest UI.**
  - ΔJ₁ is labelled "preview only" with its mode, objective and window.
  - A fixed (P04) run keeps a disabled card that shows the server's reason.
  - The frozen passport never changes.
- **Flag.** `FEATURE_RESEARCH_WHATIF` requires `WFO_PROFILE` and `FREEZE`. The Python side uses `PORTAL_FEATURE_RESEARCH_WHATIF`.

### Sibling attempt (P16-T08 / P19)

- "create sibling attempt →" opens Screen 02 at `runs/new?from=<run>&fork=<cell>`.
- The node's two values are re-read from the server's grid, never from the URL, and pinned on the copied declaration.
  A node that is not on the grid says so and pins nothing.
- Run-create takes an optional `lineage {relation: "SIBLING_OF", parent_run_id, what_if_cell_id}`.
  - The producer intent stays NEW, with its own preflight and config_hash.
  - The attempt is `CLONE_FOR_EXPERIMENT`, with `parent_attempt_id` = the frozen run's attempt and `attempts.relation_kind = 'SIBLING_OF'` (CHECK constraint).
  - The reason reads "what-if fork of <run> at <cell>".
- Lineage (S10) publishes `relation_to_parent`, and S10 prints "sibling of <attempt> — a what-if fork with its own config_hash".
- WFO admission accepts pins only on `rvol`/`slpercent`, on the declared step inside the declared range.
  Any other override, a sweep, or a widened value is refused. Widening the declaration needs a new code version (T14).
  The child applies the pins as fixed `ParameterSpec`. A what-if job never carries pins.
